# Deploying Patron on Render (one Blueprint)

The whole stack — PostgreSQL, Key Value (Redis), the API, and the admin
dashboard — is described in **`render.yaml`** at the repo root. Render reads that
one file and creates and wires everything for you. This is the easiest path for
a first live deploy: no per-service clicking, and almost no secrets to paste.

> **Security:** you only ever provide two values by hand — `ENCRYPTION_KEY`
> (generated on your own device) and `SEED_ADMIN_PASSWORD` (the admin password
> you choose). Every other secret is generated by Render. Never paste a secret
> or a database URL into a chat. If a secret was ever shown in a chat, treat it
> as burned and generate a new one.

---

## What you get

| Resource | Name | Public URL |
|---|---|---|
| API (NestJS) | `etssadagha-api` | `https://etssadagha-api.onrender.com` |
| Admin dashboard (Next.js) | `etssadagha-shop` | `https://etssadagha-shop.onrender.com` ← **your link** |
| PostgreSQL | `patron-db` | internal only |
| Key Value (Redis) | `patron-kv` | internal only |

The API **bootstraps its own database**: every boot runs `prisma migrate
deploy`, and it seeds when `SEED_ON_BOOT=true` (admin, roles, currencies,
categories, games, settings; no products). No terminal needed.

> The blueprint now ships `SEED_ON_BOOT: "false"` because this store's database
> is already seeded. **For a brand-new database, set it to `"true"` for the
> first deploy**, then back to `"false"`.

## 0. Prerequisites

- A [Render](https://render.com) account, signed in with the **GitHub account
  that owns `patron`** (so Render can read the repo).
- Two values ready:
  - **`ENCRYPTION_KEY`** — exactly **64 hexadecimal characters** (32 bytes).
    Generate it with any of:
    - a terminal: `openssl rand -hex 32`
    - Node: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
    - a client-side generator page (generated in your browser, nothing sent
      anywhere).
  - **`SEED_ADMIN_PASSWORD`** — the password you want for the admin login
    (`admin@patron.io`). Pick a strong one and save it.

## 1. Create the Blueprint

1. Render Dashboard → **New +** → **Blueprint**.
2. Connect / pick the repository **`YAHYASIDE/patron`**.
3. Set the branch to **`claude/patron-monorepo-setup-1o2gl7`** (the one that
   contains `render.yaml`). Render parses the file and lists the four resources.
4. Render prompts for the two `sync: false` variables on the API service:
   - **`ENCRYPTION_KEY`** → paste your 64-hex value.
   - **`SEED_ADMIN_PASSWORD`** → type the admin password you chose.
5. Click **Apply** / **Create resources**.

That's it. Render now builds the two Docker images, creates the database and
Key Value store, injects all the wired variables, and deploys.

## 2. Watch the first deploy

- The **API** builds, then on first boot its logs show:
  `applying migrations…` → `seeding database…` → the server listening.
- The **admin** builds and starts.
- Free services take a few minutes on the first build.

## 3. Verify

- API health: open `https://etssadagha-api.onrender.com/api/v1/health/ready`
  → should return `200` with a JSON body.
- Admin: open **`https://etssadagha-shop.onrender.com`** → the login page.
- Log in with `admin@patron.io` and the `SEED_ADMIN_PASSWORD` you set.

## 4. After the first successful deploy

- Set **`SEED_ON_BOOT`** to `"false"` in `render.yaml` (or on the API service →
  **Environment**). The seed upserts categories, currencies and settings, so
  leaving it on would undo edits you make in the dashboard every time the
  service restarts (free instances restart often).
- Add your real products from the dashboard (**المنتجات → + منتج جديد**). The
  seed no longer creates sample products (opt in locally with
  `SEED_DEMO_CATALOG=true`).

## 5. If a service URL is different

Render derives each public URL from the service name. The names here
(`etssadagha-*`) are distinctive, so collisions are very unlikely — but if
Render shows a different URL for the API (e.g. a `-xxxx` suffix was added
because the name was taken), update two variables so the admin can reach it:

1. **Admin** service → Environment → `NEXT_PUBLIC_API_URL` =
   `https://<actual-api-url>/api/v1` → **Manual Deploy / Clear build cache &
   deploy** (it is baked in at build time, so the admin must rebuild).
2. **API** service → Environment → `CORS_ORIGINS` =
   `https://<actual-admin-url>`.

## 6. Custom domain (optional, do it any time)

To serve the dashboard at **`shop.etssadagha.com`** instead of the
`onrender.com` URL:

1. Admin service → **Settings → Custom Domains** → add `shop.etssadagha.com`.
   Render shows a **CNAME target**.
2. In the DNS panel for **etssadagha.com**, add: `CNAME  shop  <target>`.
3. (Recommended) do the same for the API at `api.etssadagha.com`, then set the
   admin's `NEXT_PUBLIC_API_URL` to `https://api.etssadagha.com/api/v1` and the
   API's `CORS_ORIGINS` to `https://shop.etssadagha.com`, and redeploy the admin.

Render provisions TLS automatically once DNS resolves.

## 7. Going to production (before real customers)

The free plan is for trials: web services **sleep after ~15 min idle** (the
first request then cold-starts), free **PostgreSQL expires after ~30 days**, and
free Key Value has **no persistence**. Before real traffic:

- Upgrade `patron-db`, the two web services, and `patron-kv` to paid plans
  (edit each service's plan, or bump the `plan:` values in `render.yaml`).
- **Enable the fulfilment worker:** it is commented out at the bottom of
  `render.yaml` because background workers are not on the free plan. Uncomment
  it and give it a paid `plan`. Until it runs, orders that need automatic
  provider fulfilment stay pending (the dashboard and catalog work regardless).
- **Rotate** `ENCRYPTION_KEY` only if it was ever exposed — and note that
  rotating it makes previously-encrypted data unreadable.
- **Payments:** add `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` as variables
  when wiring real payments, and point the Stripe webhook at
  `https://<api>/api/v1/webhooks/...`.

## Variable reference (what the Blueprint sets)

Source of truth: `apps/api/src/config/env.validation.ts`.

| Variable | Set by | Notes |
|---|---|---|
| `NODE_ENV` | blueprint | `production` |
| `PORT` | blueprint | `3000` (matches the Docker healthcheck) |
| `DATABASE_URL` | `fromDatabase` | internal connection string |
| `REDIS_HOST` / `REDIS_PORT` | `fromService` | internal Key Value (no password) |
| `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` | `generateValue` | Render-generated |
| `METRICS_TOKEN` | `generateValue` | required in production |
| `ENCRYPTION_KEY` | you (`sync: false`) | 64 hex chars |
| `SEED_ADMIN_PASSWORD` | you (`sync: false`) | admin login password |
| `SEED_ON_BOOT` | blueprint | `false` (set `true` only to bootstrap a new DB) |
| `BASE_CURRENCY` | blueprint | `USD` |
| `CORS_ORIGINS` | blueprint | the admin's public origin |
