# دليل فريق الذكاء والتطوير في Patron

هذا الدليل لصاحب المتجر. يشرح من هم الوكلاء، وكيف يعملون، وما الذي تراه في اللوحة، وما الذي
لا يفعلونه أبدًا.

## 1. الفكرة باختصار

- **الوكلاء ليسوا برامج تعمل وحدها طوال الوقت.** هم أدوار محفوظة في المستودع (`.claude/agents`).
  يعملون فقط عندما تفتح جلسة Claude Code وتطلب منهم عملًا، أو عندما يشغّل GitHub الفحص اليومي.
- **الفحص اليومي** (GitHub Actions، كل يوم) يقرأ الكود والاختبارات فقط، ويكتب تقريرًا. لا يعدّل
  شيئًا ولا ينشر شيئًا.
- **الفحص داخل المتجر** (كل ليلة الساعة 03:17 بتوقيت UTC، أو بزر «افحص الآن») ينظر في المنتجات
  ووسائل الدفع حسب الدولة وأخطاء الخادم وعمليات البحث بلا نتائج.
- كل ما يُكتشف يظهر في صفحة **«مركز الذكاء والتطوير»** في لوحة التحكم، وأنت من يقرر.

## 2. الوكلاء الأحد عشر

| الوكيل | عمله | يعدّل الكود؟ |
|---|---|---|
| patron-manager (المدير) | يرتب الأولويات ويوزّع المهام، ولا يعطي وكيلين الملفات نفسها في الوقت نفسه | لا |
| market-scout (مستكشف الأسواق) | يبحث عن وسائل الدفع والعملة واللغة في كل دولة من مصادر رسمية | لا |
| business-analyst (محلل الأعمال) | المنتجات والأرباح والفرص | لا |
| security-guardian (حارس الأمان) | يراجع الصلاحيات والأسرار والثغرات | لا |
| payment-guardian (حارس المدفوعات) | يراجع كل تغيير يمس المال | لا |
| ux-designer (مصمم التجربة) | الشاشات على الهاتف والحاسوب | لا |
| app-developer (المطوّر) | ينفذ الإصلاحات في فرع مستقل مع اختبارات | نعم، في فرعه فقط |
| qa-tester (المختبِر) | يكتب الاختبارات ويشغّلها ويتحقق من الإصلاح | نعم (اختبارات) |
| automation-agent (الأتمتة) | التذكيرات والإشعارات والنسخ الاحتياطي والفحص الدوري | نعم، في فرعه فقط |
| customer-experience (تجربة الزبون) | الحسابات والدعم والمندوبون | لا |
| release-manager (مدير الإصدار) | يجهّز طلب الدمج ويتأكد أن كل الفحوص خضراء | لا |

**مسار أي إصلاح:** المدير يحدد الأولوية ← المحللون يكتبون التقرير ← المطوّر يعمل في فرعه ←
المختبِر يتحقق ← حارس الأمان أو المدفوعات يراجع إذا كان التغيير حساسًا ← مدير الإصدار يجهّز
طلب الدمج. **لا يُقبل أي إصلاح بلا اختبارات، ولا يُدمج شيء بلا موافقتك.**

## 3. ما لا يفعله أي وكيل أبدًا

- لا يدمج طلبات الدمج، ولا ينشر على Render، ولا يلمس قاعدة بيانات المتجر الحقيقي.
- لا يفعّل وسيلة دفع ولا خدمة مالية، ولا ينفذ أي تحويل حقيقي.
- لا يكتب مفاتيح أو كلمات مرور أو أرقام زبائن في التقارير (تُخفى تلقائيًا).
- لا يقدّم التخمين على أنه حقيقة: كل اكتشاف عليه «مؤكد» أو «تقدير غير مؤكد» مع نسبة ثقة.

## 4. صفحة «مركز الذكاء والتطوير»

- **العدادات:** اكتشافات جديدة، مشكلات حرجة، فرص، بانتظار المراجعة، مكتملة، مؤجلة.
- **كل اكتشاف** فيه: العنوان، الوصف، الدليل (ملف أو اختبار أو سجل)، الثقة، الخطورة، الأثر، الاقتراح،
  نتائج الاختبارات، وسجل القرارات.
- **أزرارك:** موافقة، رفض، تأجيل (بعدد أيام)، بدء التنفيذ، تم، إعادة فتح.
- **حالة الوكلاء:** آخر تشغيل لكل وكيل وماسح، ونتيجته، وتحذير «قديم» إذا لم يعمل منذ يومين.
- الاكتشاف نفسه لا يتكرر: إذا ظهر مرة أخرى يزيد عدّاده فقط. وإذا رفضته أو أنهيته لا يُعاد فتحه
  تلقائيًا.
- المشكلة الحرجة تصلك أيضًا في جرس الإشعارات.

## 5. صفحة «الدول والأسواق»

1. **إضافة دولة:** تُنشأ **معطّلة**، ويظهر اكتشاف «تحتاج بحثًا».
2. **البحث:** مستكشف الأسواق يجمع وسائل الدفع مع المصادر وتاريخ التحقق، فتظهر عندك
   «بانتظار المراجعة».
3. **قرارك:** موافقة أو رفض أو تأجيل لكل وسيلة.
4. **الموافقة وحدها لا تُظهر الوسيلة للزبائن.** يجب أن تضيف حساب استقبال لتلك الدولة في
   «وسائل الدفع» ثم تربطه بالوسيلة، فتصبح «فعّالة».
5. **كل دولة مستقلة:** زبون مالي لا يرى بنكيلي ولا مصرفي (وسائل موريتانية).
6. **تغيير الدولة لا يغيّر الطلبات القديمة** ولا أسعارها ولا طريقة دفعها.
7. **التحقق الدوري:** أي معلومة عمرها أكثر من 90 يومًا تُعلَّم «تحتاج إعادة تحقق».

مثال مالي: Orange Money Mali و Moov Money Mali تظهران «بانتظار المراجعة» مع مصادرهما. لن يراهما أي
زبون حتى توافق وتضيف رقم استقبال في مالي وتربطه.

## 6. كيف تطلب عملًا من الفريق

في جلسة Claude Code على هذا المستودع اكتب مثلًا:

- «شغّل patron-manager على الاكتشافات المفتوحة وأعطني خطة» — المدير يرتب ويوزع.
- «استخدم market-scout لإضافة السنغال» — بحث بمصادر، والنتيجة بانتظار موافقتك.
- «أصلح الاكتشاف رقم … عبر app-developer ثم qa-tester» — إصلاح في فرع مستقل مع اختبارات وطلب دمج.

ولتشغيل الجلسة كمدير مباشرة: `claude --agent patron-manager`.

## 7. الفحص اليومي في GitHub

الملف: `.github/workflows/intelligence.yml`. يعمل كل يوم ويمكن تشغيله يدويًا من تبويب
«أكشنز» (Actions). يحفظ التقرير ملفًّا مرفقًا لمدة 30 يومًا.

إعدادات اختيارية (أسرار في GitHub ← Settings ← Secrets):

| السر | ماذا يضيف | بدونه |
|---|---|---|
| `INTEL_API_URL` + `INTEL_INGEST_TOKEN` | يرسل نتائج الفحص اليومي إلى «مركز الذكاء» في لوحتك | التقرير يبقى في GitHub فقط |
| `ANTHROPIC_API_KEY` | مراجعة ذكية بالعربية يكتبها المدير فوق التقرير (اشتراك مدفوع لدى Anthropic) | الفحص الآلي يعمل كاملًا بدونها |

ويجب وضع القيمة نفسها لـ `INTEL_INGEST_TOKEN` في إعدادات الواجهة البرمجية على Render عندما تقرر
تفعيل الإرسال.
